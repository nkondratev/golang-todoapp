Раздел для администратора и разработчика: резервное копирование, диагностика, откат и риски.

## Резервное копирование

Перед внедрением новой версии создаётся копия базы данных и конфигурационных файлов. Дополнительно скрипт на Sh делает копию **каждый час**; копии хранятся в `/home/USER/backups`. Скрипт установлен в каждом Docker-контейнере по умолчанию.

## Диагностика

Если приложение не запускается или не подключается к БД:

1. Проверьте состояние контейнеров:

   ```bash
   docker compose ps
   ```

2. Изучите логи:

   ```bash
   docker compose logs
   ```

3. Проверьте параметры подключения к БД и порт API в [настройках](installation.md#настройка).

## Контрольные точки

| Точка | Критерий успеха | Если не выполнено |
|---|---|---|
| 1. После установки | Контейнеры API и БД запущены, API доступен по порту, в логах нет ошибок запуска | Анализ логов, исправление, при необходимости откат |
| 2. После настройки | Создание, получение, изменение, удаление задач работают; логи фиксируют операции | Проверка настроек API, БД и слоёв приложения, при необходимости откат |

## План отката

**Когда откатываться:** новая версия не запускается, контейнеры падают с ошибками, нет подключения к БД или не работают основные операции — и критическая ошибка не устранена за **30 минут**. Решение принимает разработчик или ответственный за внедрение.

1. Остановите контейнеры новой версии:

   ```bash
   docker compose down
   ```

2. Верните предыдущую версию Docker-образа TODO API.
3. При необходимости восстановите БД и конфигурацию из резервной копии.
4. Запустите предыдущую версию:

   ```bash
   docker compose up -d
   ```

5. Проверьте работу:

   ```bash
   docker compose ps
   curl http://localhost:8080/tasks
   ```

Откат успешен, если контейнеры запущены, основные операции работают и в логах нет критических ошибок.

> **Фиксируйте причину.** В журнале внедрения запишите ошибку, время, действия по откату, результат и рекомендации перед повторной попыткой.

## Риски

| Риск | Вероятность | Меры |
|---|---|---|
| Технический: ошибка сборки или запуска контейнеров | Средняя | Проверить `Dockerfile` и `docker-compose.yml`, тестовый запуск, анализ логов |
| Потеря данных при обновлении | Низкая | Резервная копия БД и конфигурации перед внедрением |
| Несовместимость версий API, БД и конфигурации | Низкая | Зафиксировать версии образов и зависимостей, проверить на тестовом запуске |
