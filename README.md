# Todo Application — «Задачи онлайн»

Веб-приложение для ведения списка задач: REST API на Go, база данных PostgreSQL и готовый веб-интерфейс, который открывается прямо в браузере. Приложение позволяет заводить пользователей, назначать им задачи, отмечать выполнение и смотреть статистику.

## Для кого это приложение

- **Пользователям** — небольшим командам и отдельным людям, которым нужен простой список задач с учётом автора, времени создания и времени выполнения. Работать можно через веб-интерфейс, ничего не устанавливая, кроме самого приложения.
- **Разработчикам** — как пример REST API на Go со слоистой архитектурой (транспорт → сервис → репозиторий), миграциями, Swagger-документацией, Docker-окружением и логированием. Подходит как основа для собственного сервиса.
- **Тем, кто интегрирует задачи в другие системы** — любой клиент (скрипт, мобильное приложение, другой сервис) может работать с приложением по HTTP и JSON.

## Возможности

**Пользователи**
- создание пользователя (ФИО и необязательный номер телефона);
- просмотр списка пользователей с постраничной выдачей (`limit`, `offset`);
- просмотр, изменение и удаление пользователя по ID.

**Задачи**
- создание задачи: название, необязательное описание и автор (существующий пользователь);
- список задач с постраничной выдачей и фильтром по автору;
- просмотр, изменение и удаление задачи по ID;
- отметка о выполнении: при `completed: true` автоматически проставляется время выполнения (`completed_at`), при `completed: false` оно сбрасывается;
- частичное обновление (PATCH) с тремя состояниями поля: не передано — не меняется, передано значение — устанавливается, передан `null` — очищается (только для описания).

**Статистика**
- количество созданных и выполненных задач;
- процент выполненных задач;
- среднее время выполнения задачи;
- фильтры по пользователю и по периоду дат.

**Сервисные возможности**
- веб-интерфейс с вкладками «Задачи», «Пользователи», «Статистика»;
- интерактивная документация API (Swagger UI);
- контроль версий записей: при одновременном изменении одной записи возвращается ошибка `409 Conflict`, а не молчаливая перезапись чужих правок;
- проверка данных на уровне приложения и на уровне базы данных (длины полей, формат телефона, согласованность выполнения задачи);
- сквозной идентификатор запроса `X-Request-ID` во всех ответах и логах;
- настраиваемый CORS, обработка паники без падения сервера, корректное завершение работы по сигналам `SIGINT` / `SIGTERM`;
- структурированные логи в файлы.

## Технологии

| Область | Что используется |
|---|---|
| Серверная часть | Go, стандартная библиотека `net/http` |
| База данных | PostgreSQL 18, драйвер `pgx`, миграции `migrate/migrate` |
| Документация API | Swagger (`swaggo`) |
| Конфигурация | переменные окружения (`envconfig`) |

| Клиентская часть | HTML, CSS, JavaScript (один файл `public/index.html`) |

## Быстрый старт

### Что понадобится

- Docker и Docker Compose;
- Make;
- Go 1.26.2 или новее — только если запускать приложение без Docker.

### 1. Получение проекта и настройка окружения

```bash
git clone https://github.com/nkondratev/golang-todoapp.git
cd golang-todoapp
cp .env.example .env
```

Откройте файл `.env` и заполните параметры базы данных (они пустые в примере):

```env
POSTGRES_USER=todo
POSTGRES_PASSWORD=придумайте_пароль
POSTGRES_DB=todoapp
```

Файл `.env` добавлен в `.gitignore` и не попадёт в репозиторий.

### 2. Запуск в Docker (рекомендуется)

```bash
make env-up          # запустить PostgreSQL
make migrate-up      # создать таблицы в базе данных
make todoapp-deploy  # собрать и запустить приложение
```

Приложение будет доступно по адресу **http://127.0.0.1:5050**:

| Адрес | Что открывается |
|---|---|
| http://127.0.0.1:5050/ | веб-интерфейс |
| http://127.0.0.1:5050/swagger/ | Swagger UI с описанием API |
| http://127.0.0.1:5050/api/v1 | базовый адрес REST API |

Остановить приложение: `make todoapp-undeploy`, остановить базу данных: `make env-down`.

### 3. Запуск без Docker для приложения (режим разработки)

База данных по-прежнему запускается в Docker, а само приложение — локально:

```bash
make env-up              # PostgreSQL
make env-port-forward    # открыть порт 5432 базы данных на localhost
make migrate-up          # миграции
make todoapp-run         # запуск приложения из исходного кода
```

Закрыть проброс порта: `make env-port-close`.

## Как пользоваться

### Через веб-интерфейс

Откройте http://127.0.0.1:5050/. Интерфейс состоит из трёх вкладок. Поля, помеченные `*`, обязательны.

**Рекомендуемый порядок работы:**

1. Перейдите на вкладку **«Пользователи»** и создайте пользователя: введите ФИО (не короче 3 символов) и при желании телефон в формате `+79998887766`. После создания запомните его `id` — он понадобится для задач.
2. Перейдите на вкладку **«Задачи»**, в блоке «Создать задачу» укажите `user_id` автора, название и при необходимости описание, нажмите «Создать».
3. Блок «Список задач» показывает созданные задачи. Можно отфильтровать их по автору и настроить `Limit` и `Offset`, затем нажать «Обновить».
4. В блоке «Получить / изменить / удалить задачу» введите ID задачи. Кнопка «Получить» показывает данные задачи, «Сохранить изменения» применяет новые название, описание или признак «Выполнена», «Удалить» удаляет задачу.
5. На вкладке **«Статистика»** можно получить сводку по всем задачам или только по одному пользователю и/или за выбранный период (поля `User ID`, `From`, `To`).

Вкладка «Пользователи» устроена так же, как «Задачи»: создание, список с пагинацией, получение, изменение и удаление по ID.

> Интерфейс обращается к API по адресу `http://127.0.0.1:5050/api/v1`, поэтому открывайте его по адресу `127.0.0.1`. Если вы открываете страницу как `localhost`, убедитесь, что `http://localhost:5050` есть в `ALLOWED_ORIGINS`.

### Через Swagger UI

Откройте http://127.0.0.1:5050/swagger/, выберите нужный метод, нажмите «Try it out», заполните параметры и выполните запрос. Это удобный способ изучить API без написания кода.

### Через командную строку (curl)

```bash
# создать пользователя
curl -X POST http://127.0.0.1:5050/api/v1/users \
  -H "Content-Type: application/json" \
  -d '{"full_name": "Ivan Ivanov", "phone_number": "+79998887766"}'

# создать задачу (author_user_id — id пользователя)
curl -X POST http://127.0.0.1:5050/api/v1/tasks \
  -H "Content-Type: application/json" \
  -d '{"title": "Домашнее задание", "description": "Сделать до четверга", "author_user_id": 1}'

# отметить задачу выполненной
curl -X PATCH http://127.0.0.1:5050/api/v1/tasks/1 \
  -H "Content-Type: application/json" \
  -d '{"completed": true}'

# очистить описание задачи
curl -X PATCH http://127.0.0.1:5050/api/v1/tasks/1 \
  -H "Content-Type: application/json" \
  -d '{"description": null}'

# список задач автора с пагинацией
curl "http://127.0.0.1:5050/api/v1/tasks?user_id=1&limit=10&offset=0"

# статистика за период
curl "http://127.0.0.1:5050/api/v1/statistics?user_id=1&from=2026-10-01&to=2026-11-01"
```

## REST API

Базовый адрес: `/api/v1`. Формат данных — JSON. Полное интерактивное описание доступно в Swagger UI (`/swagger/`).

### Пользователи

| Метод | Путь | Описание | Успешный ответ |
|---|---|---|---|
| `POST` | `/users` | Создать пользователя | `201` |
| `GET` | `/users` | Список пользователей (`limit`, `offset`) | `200` |
| `GET` | `/users/{id}` | Получить пользователя | `200` |
| `PATCH` | `/users/{id}` | Изменить пользователя | `200` |
| `DELETE` | `/users/{id}` | Удалить пользователя | `204` |

Поля пользователя: `id`, `version`, `full_name`, `phone_number`.

Правила: `full_name` — от 3 до 100 символов; `phone_number` необязателен, должен начинаться с `+`, содержать только цифры после него и быть длиной от 10 до 15 символов.

### Задачи

| Метод | Путь | Описание | Успешный ответ |
|---|---|---|---|
| `POST` | `/tasks` | Создать задачу | `201` |
| `GET` | `/tasks` | Список задач (`user_id`, `limit`, `offset`) | `200` |
| `GET` | `/tasks/{id}` | Получить задачу | `200` |
| `PATCH` | `/tasks/{id}` | Изменить задачу | `200` |
| `DELETE` | `/tasks/{id}` | Удалить задачу | `204` |

Поля задачи: `id`, `version`, `title`, `description`, `completed`, `created_at`, `completed_at`, `author_user_id`.

Правила: `title` — от 1 до 100 символов, обязателен; `description` необязательно, от 1 до 1000 символов; `author_user_id` обязателен и должен указывать на существующего пользователя (иначе `404`).

При изменении через `PATCH` можно передавать любое подмножество полей `title`, `description`, `completed`. Поля `title` и `completed` нельзя установить в `null`.

### Статистика

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/statistics` | Статистика по задачам |

Параметры (все необязательные): `user_id`, `from` — начало периода включительно, `to` — конец периода не включительно; даты в формате `YYYY-MM-DD`.

Пример ответа:

```json
{
  "tasks_created": 50,
  "tasks_completed": 10,
  "tasks_completed_rate": 20,
  "tasks_average_completion_time": "1m30s"
}
```

`tasks_completed_rate` — процент выполненных задач, `tasks_average_completion_time` — среднее время от создания до выполнения. Если задач за выбранный период нет, показатели нулевые.

### Коды ответов и ошибки

| Код | Когда возвращается |
|---|---|
| `200`, `201`, `204` | запрос выполнен |
| `400` | некорректные данные: неверный формат, нарушение ограничений, отрицательный `limit` |
| `404` | запись не найдена (в том числе автор при создании задачи) |
| `409` | запись была изменена другим запросом, повторите операцию |
| `500` | внутренняя ошибка сервера |

Ошибки возвращаются в виде JSON:

```json
{
  "error": "task with id='7': not found",
  "message": "failed to get task"
}
```

> Задачи ссылаются на пользователя внешним ключом без каскадного удаления, поэтому пользователя, у которого есть задачи, сначала нужно освободить от них — удалите или перенесите его задачи.

## Настройка

Все параметры задаются переменными окружения (файл `.env`, образец — `.env.example`).

| Переменная | Описание | Значение по умолчанию / пример |
|---|---|---|
| `HTTP_ADDR` | адрес и порт HTTP-сервера | `:5050` |
| `HTTP_SHUTDOWN_TIMEOUT` | время на корректное завершение работы | `30s` |
| `ALLOWED_ORIGINS` | разрешённые источники CORS, через запятую | `http://localhost:5050,null` |
| `POSTGRES_USER` | пользователь базы данных | *обязательно* |
| `POSTGRES_PASSWORD` | пароль базы данных | *обязательно* |
| `POSTGRES_DB` | имя базы данных | *обязательно* |
| `POSTGRES_TIMEOUT` | таймаут операций с базой данных | `10s` |
| `POSTGRES_HOST` | адрес базы данных (в Docker задаётся автоматически) | `todoapp-postgres` / `localhost` при локальном запуске |
| `POSTGRES_PORT` | порт базы данных | `5432` |
| `LOGGER_LEVEL` | уровень логирования | `DEBUG` |
| `LOGGER_FOLDER` | каталог для файлов логов (в Docker и `make todoapp-run` задаётся автоматически) | `out/logs` |
| `TIME_ZONE` | часовой пояс приложения | `UTC` |

## Архитектура и структура проекта

Каждая функция приложения (пользователи, задачи, статистика, веб-страница) разделена на три слоя:

- **transport/http** — приём запроса, разбор и проверка параметров, формирование ответа;
- **service** — бизнес-логика;
- **repository** — работа с PostgreSQL.

Общие компоненты вынесены в `internal/core`.

```
.
├── cmd/todoapp/              точка входа и Dockerfile
├── internal/
│   ├── core/                 домен, конфигурация, логгер, HTTP-сервер, middleware, пул соединений
│   └── features/
│       ├── users/            пользователи
│       ├── tasks/            задачи
│       ├── statistics/       статистика
│       └── web/              отдача веб-интерфейса
├── migrations/               SQL-миграции базы данных
├── public/index.html         веб-интерфейс
├── docs/                     сгенерированная Swagger-документация
├── documentation/            пользовательская и разработческая документация
├── out/logs/                 файлы логов
├── docker-compose.yaml       окружение: приложение, PostgreSQL, миграции, Swagger
└── Makefile                  команды управления проектом
```

Каждый запрос последовательно проходит через middleware: CORS → идентификатор запроса → логирование → трассировка (время обработки и код ответа) → перехват паники.

## Логи и тесты

Логи записываются в каталог `out/logs` отдельным файлом на каждый запуск приложения; каждая запись содержит `request_id` запроса. В Docker этот каталог подключён к контейнеру, поэтому логи доступны на хост-машине.

Запуск тестов:

```bash
make test
# или с замером покрытия
go test -cover ./...
```
